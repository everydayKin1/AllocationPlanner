# 幻想シアター公演配分プランナー

各幕の敵に合わせてキャラを配置し、招待回数・バフ・幻戯の花をシミュレーションできる静的Webアプリです。ビルド不要（HTML/CSS/JS＋画像だけ）。データは各ユーザーのブラウザ（localStorage）に保存され、サーバーには送りません。

- **公開URL**：https://everydaykin1.github.io/AllocationPlanner/
- **ホスティング**：GitHub Pages（リポジトリ `everydayKin1/AllocationPlanner` の `main` / `(root)`）
- **ローカルで開くとき**：`index.html` をブラウザで直接開くか、このフォルダで簡易サーバーを立てて開く

配布・公開に必要なのはこの4ファイルです（画像を使う場合は `images/` フォルダも一緒に）。

- `index.html`
- `styles.css`
- `app.js`
- `master-data.js`

---

## ⚠️ 作業を始める前に必ず `git pull`

`master-data.js` は **GitHub 上で自動更新される**ため、パソコンの中のファイルは自動では新しくなりません。Notion を編集した翌日などは、GitHub の方だけが新しい状態になっています。

```bash
git pull
```

**キャラや月データを変えたいときは、パソコンの `master-data.js` を書き換えないでください。** Notion 側を編集すれば自動で反映されます。手で書き換えると、次の自動実行で上書きされたり、コミットがぶつかったりします。

（`styles.css` や `app.js` など、Notion 管理外のファイルはこれまでどおりパソコンで編集してOKです。）

## 🔁 更新のしかた（公開サイトへの反映）

ファイルを直したら、**コミット → push するだけ**で1〜2分後に公開サイトへ自動反映されます。

- GitHub Desktop：変更を確認 → **Commit to main** → **Push origin**
- ターミナル：
  ```bash
  cd "パス/幻想シアター用・files"
  git add -A
  git commit -m "更新内容のメモ"
  git push
  ```

## ⏰ キャッシュ対策の `?v=` について

`index.html` の読み込み行には `?v=27` のような**バージョン番号**が付いています（`styles.css?v=27` / `app.js?v=27` / `master-data.js?v=27`）。これを上げないと、**前に開いた人のブラウザが古いキャッシュのまま**になり修正が反映されません。

| 変えたもの | `?v=` の扱い |
| --- | --- |
| **Notion のデータ**（キャラ・月次・敵） | **自動**。GitHub Actions が繰り上げてコミットします |
| `styles.css` や `app.js` を手で編集 | **手動で +1** してから push |
| 画像を追加・差し替え | **手動で +1**（`images/` に置いて Notion 側のファイル名を合わせる） |
| `README.md` など表示に関係ない文書だけ | そのままでOK |

手で上げるのが面倒なときは、このコマンドでも繰り上がります。

```bash
python3 tools/bump_version.py
```

> メモ：`?v=` は**数字を上げるほど新しい版**として扱われる通し番号です。3行は同じ数字に揃えておくと管理がラクです。

## 🗓 定期的にやること

- **毎月（新しい月が始まったら）**：**Notion の「月次設定」と「幕と敵」に行を足すだけ**です。GitHub Actions が毎日拾いに行き、`master-data.js` と `?v=` を自動更新します。
  - 手順は下記「[Notion からの自動更新](#-notion-からの自動更新)」を参照。
  - 急いで反映したいときは Actions タブから手動実行できます。

## 画面モード（計画／進行）

2つのモードがあり、ヘッダーの「進行モードへ／計画モードへ」（スマホは下タブの「進行」）で切り替えます。**配置・招待回数・バフは両モードで共有**されるので、計画で組んだ編成がそのまま進行モードに出ます。表示モードはタブごとに独立です。

### 計画モード
全12幕を一覧して編成を組み立てる画面。各幕で キャラ招待／シャイニングブレス／観客からの応援 を増減でき、幻戯の花の残量が全幕に波及します。

### 進行モード
実際にゲームを進めながら1幕ずつ見る画面。

- **左上**：現在の幕と、相性のいい要素／悪い要素
- **右上**：敵の情報（選択制の幕は ♻ アイコンで敵を切り替え）
- **配置枠4つ**：横に並ぶタイル。下に編成状況（元素の内訳、月兆・初照／満照、魔導秘儀）
- **公演成功後のキャラ加入**と**星章獲得**のチェック
- **出演可能キャラ**：活力マーク付き。相性◎は👍、相性✕は赤、活力切れは薄く表示
- **この先の見通し**：次の幕の敵と、以降の幕ごとに「特攻要素を持ち活力が残っているキャラ」の人数（行をタップでアイコン展開。待機キャストは🔒付き）
- **右サイド**：12幕のレールと、アルカナ挿入位置（常時表示）

**出演可能キャラは開幕キャスト6名から始まり**、加入を登録するたびに増えます。

| 加入のしかた | いつから使える | 招待回数 |
| --- | --- | --- |
| 公演成功後の加入（最終幕を除き毎戦闘1名） | 次の幕から | 変わらない |
| キャラ招待（幻戯の花がある限り何回でも／0回でもOK） | その幕から | 自動で+1 |

加入したキャラは**活力が残っていれば以降ずっと**使えます。4枠が埋まっていない状態で「次の幕 ▶」を押すと警告が出て止まり、もう一度押すと進みます。

## モーダル（下タブ／ヘッダーから開く）

- **編成状況**：待機キャストの選抜、元素ごとの人数、今月の主人公の元素、ボス相性チェック。右下の丸ボタンで絞り込み
- **キャラ一覧**：所持状況・レベル・**凸（C0〜C6）**・個人メモを編集。元素で絞り込み＋名前検索。未所持は下に別枠表示
- **設定**：ナイトモード、書き出し／読み込み、今月のデータの初期化
- **使い方**：遊び方と計算ルールの説明

## 🔄 Notion からの自動更新

`master-data.js` のキャラと月次データは、Notion のデータベースから**自動生成**されます。

### 仕組み

| Notion のデータベース | 役割 |
| --- | --- |
| 幻想シアター・キャラクター一覧 | キャラ全員（元素・レベル・タグなど） |
| 幻想シアター・月次設定 | 月ごとの出演元素・開幕/特別招待キャスト・バフ名 |
| 幻想シアター・幕と敵 | 各幕の敵情報（1行＝敵候補1つ） |

GitHub Actions が**毎日 日本時間3:00**に Notion を読みに行き、`master-data.js` に差分があれば自動でコミットします。手動実行したいときは、GitHubの **Actions タブ → 「Notion から master-data.js を更新」→ Run workflow**。

反映されると、閲覧者のキャッシュ対策として `index.html` の `?v=` も自動で繰り上がります。

### 毎月やること

Notion で以下を足すだけです（アプリ側の変更は不要）。

1. **月次設定**に新しい行を追加（例 `2026-10`）。出演元素・主人公の元素・バフ名3つ・開幕キャスト6名・特別招待キャストを入れる
2. **幕と敵**に、その月の敵を追加。1行＝敵候補1つで、`Month`（月次設定へのリレーション）と `StageId`（`act-1`〜`act-10`, `arcana-1`, `arcana-2`）を指定
   - 選択制の幕は候補ごとに行を作り、`Option` に 1／2／3 を入れる
   - ボス表記にしたい幕だけ `StageName` に `第3幕（ボス）` のように入れる（空欄なら既定名）
   - `GoodElement` / `GoodTags` が相性◎、`AvoidElement` / `AvoidTags` が相性✕（**入れた時だけ**✕が出ます）
   - `RequireAll` を ON にすると「元素**かつ**タグ」を満たすキャラだけが相性◎になります

新しい月を追加すると、アプリは次に開いたとき自動でその月を表示します。

> **幕の報酬・特別挑戦・解放条件は毎月同じ**なので Notion では管理していません。`tools/notion_to_master.py` の先頭で固定しています（第3/6/8幕=125、第10幕=0、アルカナは第3幕/第6幕クリア後から）。

### 手元で試すとき

```bash
# 変換ロジックだけ検証（ネット接続もAPIキーも不要）
python3 tools/notion_to_master.py --selftest

# 実際に Notion から生成する
NOTION_API_KEY=あなたのトークン python3 tools/notion_to_master.py
```

APIキーは GitHub の **Settings → Secrets and variables → Actions** に `NOTION_API_KEY` として登録済みです。Notion 側でデータベースの**列名を変更すると壊れる**ので、変えたときは `tools/notion_to_master.py` も合わせて直してください（列が見つからない場合はエラーで止まり、既存ファイルは壊しません）。

## 保存の分担

管理者（あなた）が更新するのは次の2か所です。

**Notion で編集**（自動で `master-data.js` に反映）
- 月ごとの出演元素・開幕キャスト・特別招待キャスト・バフ名・敵情報（相性◎／✕を含む）
- キャラ名、画像、レベル、元素、固定タグ

**`master-data.js` を直接編集**（Notion 管理外。めったに変えない部分）
- 聖遺物セット一覧（`artifactSets`）と、用語ツールチップの文言（`glossary`）
- ブランドアイコン（`icons`：ブラウザタブ・タイトル横・幻戯の花・元素・プネウマ/ウーシア・月兆・魔導）
- 共通ルール（`rules`：活力上限・招待コスト・応援の花量など）

> 自動更新は `characters` と `months` の2ブロックだけを書き換えます。それ以外は触りません。

各ユーザーがブラウザ（localStorage）に保存するのは次です。サーバーには送りません。

- 月ごとのキャラ配置・招待数・バフ取得数・観客からの応援・メモ
- アルカナの挿入位置
- 進行モードの現在の幕、加入キャラの記録（誰がどの幕で、公演成功後か招待か）、星章の獲得状況
- 今月の主人公の元素
- 所持しているかどうか（初期状態はすべて「所持済み」）
- レベル（初期値90、1〜100で編集可能）と凸（C0〜C6）
- 「今月これを編成に入れる」チェック（開幕キャスト以外）
- 各キャラの聖遺物セット（同じ幕に同じセットが重なると警告バッジが出ます）
- 「所持チェックボックスを表示する」などの表示設定

この一覧はアプリ内の**設定タブ →「このアプリが保存しているデータ」**でも確認できます。

同じページを**複数のタブで開いても大丈夫**です。片方で変更すると、もう片方も自動で追いつきます（取り込んだときは画面下に通知が出ます）。ブラウザの設定で保存が制限されている場合は、その旨を知らせたうえでアプリは動き続けます。

> ※ 初期化の取り消し用データはメモリ上だけなので、ページを再読み込みすると「元に戻す」はできなくなります。

## 役割タグ

キャラの `roles` に付けられるタグです。敵の「相性のいいタグ／悪いタグ」にも同じ名前が使えます。

| タグ | 用途 |
| --- | --- |
| アタッカー / サポーター / ライフキーパー | 従来の3分類。そのまま使えます |
| ヒーラー / シールダー / タンク | ライフキーパーの中身をさらに細かく分けるための追加タグ |

追加タグは**既存の分類を置き換えるものではありません**。「ライフキーパー」と「ヒーラー」を両方付けてかまいませんし、既存キャラのデータを直す必要もありません。

> 追加タグにはアイコン画像がないため、絞り込みでは**文字のまま横長のピル**で表示されます。`images/icon/` に画像を置いて `master-data.js` の `icons.roles` に登録すれば、アイコン表示に切り替わります。

## キャラ一覧の並び順

モーダルの「キャラ一覧」は次の優先順で並びます。**未所持は常に下のセクション**にまとまります。

1. **レベルの高い順**
2. **レアリティ**（5★が先、4★があと）
3. **実装順**（新しいキャラほど上）

そのため `characters` には `rarity`（5 か 4）と `releaseOrder`（実装順の通し番号。数字が大きいほど新しい）が入っています。

主人公は**全元素ぶん**が並びます（今月使えるのは1体でも、レベルや凸は元素ごとに記録するため）。

### 新しいキャラを足したとき

Notion の「キャラクター一覧」に `Rarity` と `ReleaseOrder` の列があります。**空欄でも動きます**——その場合は既存の値を引き継ぎ、まったく新しいキャラなら「いちばん新しい」として自動で番号が振られ、レアリティは 5 と仮置きされます。4★のときだけ Notion で `Rarity` を 4 にしてください。

## 主人公のアイコン

設定タブで「空」「蛍」を選ぶと、**元素を問わず主人公すべて**のアイコンが切り替わります。画像は `master-data.js` の `icons.traveler` で指定しています。

```js
traveler: { "空": "./images/character/Aether_icon.webp", "蛍": "./images/character/Lumine_Icon.webp" }
```

## 使えるキャラの判定ルール

一覧はデフォルトで「今月使えるキャラだけ」を表示します（「今月使えないキャラも表示する」で全表示）。判定は次のとおりです。

- 開幕キャスト … 常に使える（所持・レベル不問）
- 主人公 … 「今月の主人公の元素」で選んだ1体だけ使える
- それ以外 … 所持している ＋ レベル70以上 ＋（今月の出演元素 または 特別招待キャスト）

## 月データの形式（参考）

> 通常は Notion で編集するため、ここを手で書き換える必要はありません。生成結果の形式を確認したいときの参考です。

`months` に月を追加・編集します。バフの `id` は `buffA` / `buffB` / `buffC` のまま固定にしてください（配置データが月をまたいでも壊れません）。名前だけ月ごとに変えられます。

```js
{
  id: "2026-09",
  label: "2026年09月",
  elements: ["水", "雷", "草"],          // 今月の出演元素3種
  travelerElements: ["水", "雷", "草"],  // 主人公として選べる元素（出演元素のうち主人公が存在するもの）
  openingCast: ["cyno", "kukishinobu", "columbina", "xingqiu", "lauma", "kaveh"], // 開幕キャスト6名（idで指定）
  specialCast: ["sandrone", "nicole", "sucrose", "odette"], // 特別招待キャスト（元素外でも所持していれば使える）
  buffs: [
    { id: "buffA", name: "過負荷" },
    { id: "buffB", name: "溶解" },
    { id: "buffC", name: "超伝導" }
  ],
  icons: [
    { label: "炎", icon: "炎" },
    { label: "水", icon: "水" },
    { label: "雷", icon: "雷" }
  ],
  stages: [
    { id: "act-1", name: "第1幕", reward: 90, allowedElements: ["炎", "水", "雷"], enemy: { name: "敵の名前", icon: "剣", note: "備考" } }
    // act-1〜act-9、arcana-1、arcana-2、act-10 まで
  ]
}
```

- 開幕キャストや特別招待は `characters` に登録済みの `id` を書きます。
- 主人公は元素ごとに `tr-fire` `tr-water` … として登録済みです。`travelerElements` に元素名を並べれば選択肢に出ます（例：氷の主人公は存在しないので8月は `["風","岩"]`）。

## キャラデータ

> 通常は Notion の「キャラクター一覧」で編集します。ここは生成結果の形式の参考です。

```js
{
  id: "furina",
  name: "フリーナ",
  element: "水",
  level: 90,
  image: "./images/character/Furina_icon.webp",
  tags: {
    positions: ["オフフィールド"],            // オンフィールド / オフフィールド（複数可）
    roles: ["サポーター", "ライフキーパー"],  // アタッカー / サポーター / ライフキーパー（複数可）
    weapon: "片手剣",                        // 片手剣 / 両手剣 / 法器 / 弓 / 長柄武器
    nightsoul: false,                        // true のときだけ「夜魂の加護」を表示
    pneumaOusia: "ウーシア",                 // プネウマ / ウーシア / 空文字（両方持ちは配列）
    lunar: false,                            // true のときだけ「月兆」を表示
    magic: true                              // true かつ Lv70以上で「魔導」を表示（ユーザー側で非表示可）
  }
}
```

主人公は `isTraveler: true` と `exclusiveGroup: "traveler"` を持ちます。所持状態は各ユーザーがブラウザ側で管理するので、`characters` に所持フラグは書きません。

`id` は紐付けのキーです。名前を変えても `id` が同じなら、ユーザーの保存済み配置とつながります。

## キャラ画像の紐付け

`images/character/` のようなフォルダを作り、`master-data.js` の `image` に相対パスを書きます（例：`./images/character/furina.png`）。空文字なら元素色の頭文字アイコンになります。

## 共通ルール（`rules`）

Notion 管理外です。`master-data.js` を直接編集します。

```js
rules: {
  maxVitality: 2,      // キャラ1人が出られる回数
  slotsPerStage: 4,    // 1幕に配置する人数
  inviteCost: 80,      // キャラ招待1回の幻戯の花
  buffCost: 60,        // シャイニングブレス1段階の幻戯の花
  cheerGain: 25,       // 観客からの応援1回で増える幻戯の花
  buffMaxLevel: 4,     // バフの上限レベル
  rosterMin: 22,       // 待機キャストの下限（公演開始に必要）
  rosterMax: 26,       // 待機キャストの上限
  defaultReward: 90
}
```

## アイコン・画像の差し込み口

`master-data.js` の `icons` に画像パスを入れると、空文字の代わりに反映されます。

```js
icons: {
  favicon: "./images/favicon.png",       // ブラウザタブのアイコン
  header: "./images/title-icon.png",     // タイトル横のアイコン
  flower: "./images/flower_icon.png",    // 幻戯の花アイコン（サマリーの「最終幻戯の花」や各幕の消費表示で使用中）
  elements: { "炎": "./images/elem_pyro.png" },
  pneuma: "./images/pneuma_icon.png",
  ousia: "./images/ousia_icon.png",
  lunar: "./images/lunar_icon.png",
  magic: "./images/magic_icon.png",
  nightsoul: "./images/nightsoul_icon.png"
}
```

空文字のままなら、`images/default-theater-icon.svg`（劇場アイコンの仮画像）がタブ・タイトル両方に使われます。

## 聖遺物セット

`artifactSets` に登録済みの10セットから、キャラごとに装備セットをユーザーが選べます（キャラ詳細の「聖遺物セット」欄）。同じ幕に同じセットのキャラが2名以上いると、配置表に警告バッジが出ます。アイコン画像は `artifactSets` の `icon` にパスを入れてください（現在は名前バッジのみ表示、画像は今後反映予定の差し込み口です）。

## 敵タグとおすすめ表示

`stages` の `enemy.tags` に `["夜魂の加護"]` のようにタグを設定すると、そのタグを持つキャラを幕に配置したときに★マークが付きます。また、スロット下に「この幕と相性が良さそうなキャラ」がおすすめとして自動で並びます（活力の残数は問いません）。

`enemy.tags` には固定タグ（夜魂の加護・月兆・魔導・プネウマ/ウーシア）・役割（オンフィールド等）・武器種だけでなく、`"炎"` のような元素名も指定できます（そのキャラの `element` と一致すればマッチします）。元素だけを指定したい場合は `enemy.element: ["雷"]` のように別枠で書いてもOKです（`tags` と自動でまとめて判定されます）。

特定のキャラを名指しでおすすめしたい場合は `enemy.recommendedCharacterIds: ["furina", "hutao"]` のようにキャラの `id` を配列で指定してください。`tags` と併用でき、`tags` がなくても `recommendedCharacterIds` だけでおすすめ表示を出せます。

### 相性の悪い要素（回避）

進行モードで「この敵には向かないキャラ」を赤く警告できます。**登録した幕にだけ**表示され、書かなければ何も出ません（「相性◎でなければ×」という判定はしません）。

```js
enemy: {
  name: "バトルシップ",
  element: ["炎"],                 // 相性のいい要素（◎）
  avoidElement: ["氷"],            // 相性の悪い元素（✕）
  avoidTags: ["ライフキーパー"]     // 相性の悪いタグ（✕）
}
```

- `avoidElement` … キャラの元素と一致したら✕
- `avoidTags` … 相性欄と同じ語彙が使えます。役割は **アタッカー / サポーター / ライフキーパー** の3種のみ（耐久・回復・盾はまとめて「ライフキーパー」）。ほかに 夜魂の加護・月兆・魔導・プネウマ/ウーシア・オンフィールド/オフフィールド・武器種も指定できます。
- ◎と✕の両方に当たるキャラは、両方のマークが出ます（情報を消しません）。

## 選択制の幕（敵を3種類から選ぶ幕）

第1・2・4・5・7・9幕は「3種類の敵札から1つを選んで戦う」形式です。この場合、`stage.enemy` の代わりに `stage.enemyOptions` に敵情報の配列を入れてください。

```js
{
  id: "act-1",
  name: "第1幕",
  reward: 90,
  enemyOptions: [
    { name: "群れの先鋒A", icon: "剣", note: "小型が多め。", tags: ["夜魂の加護"] },
    { name: "群れの先鋒B", icon: "盾", note: "単体寄り。" },
    { name: "群れの先鋒C", icon: "晶", note: "耐性が高め。", element: ["雷"] }
  ]
}
```

各項目は `enemy` と同じ形式（`name`/`icon`/`note`/`tags`/`element`/`recommendedCharacterIds`）です。画面上ではアイコン付きのチップが並び、クリックした敵の情報が上のボックスに表示されます（選んだ内容はブラウザに保存されます）。`enemyOptions` を書かなければ、これまで通り `enemy` 1件だけの表示になります。

第3・6・8・10幕とアルカナ挑戦2は必ず単体のネームドボスなので、`enemyOptions` は不要で `enemy` のままでOKです。

## 用語ツールチップ

`glossary` の文言が、バフ・夜魂の加護・月兆・魔導・プネウマ/ウーシア・聖遺物セット重複の説明として、画面上の「ⓘ」アイコンから表示されます。文言は自由に書き換えられます。
